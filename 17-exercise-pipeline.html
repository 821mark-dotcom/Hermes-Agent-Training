The Full Pipeline

⏱ 25 minIntermediateAdvanced
🎯 Exercise Goal

Configure a team in Operations, route a mission through Swarm's worker dispatch, and use the Dashboard Kanban as your command center — watching tasks move from Triage through to Done as your specialist agents pick them up in sequence. This exercise connects every component you've learned into one end-to-end workflow.

ELI10

You're the project manager. Operations is where you build your team (who the agents are and what they're good at). Swarm is how you send a mission to the whole team at once. The Kanban board is the project tracker you keep open on a second screen — it shows every task, who's working on it, what they found, and what's next. In this exercise you set up all three and let them talk to each other.

⚡ Pre-requisites — confirm before starting:
  • Section 15 profile bootstrap complete: hermes profile list shows researcher, writer, reviewer, builder
  • Gateway running: hermes gateway start (check localhost:9119)
  • Workspace running: localhost:3000 loads without error
  • Board is empty or clean: archive any tasks from previous exercises
📋 Expected Output: Operations shows at least 2 active agent sessions. Swarm routes a mission to 2+ parallel workers. Dashboard Kanban shows a task graph with parent-child links. At least 1 worker completes its task and the completion summary is visible in the next task's context.

Phase 1 — Verify Your Team in Operations

  1. Open Operations in Hermes Workspace
    Navigate to localhost:3000/operations. You'll see the agent roster grid. If it shows "Needs setup" flags, the profiles don't have their gateway started. Note which profiles are available.
  2. Confirm profile descriptions via Dashboard Kanban Orchestration Settings
    Open localhost:9119/kanban → click ▸ Orchestration settings. You'll see each profile with its description. Verify researcher, writer, reviewer, and builder each have a non-empty description. If any is missing, add it here (inline editor — click the profile name).
  3. Launch a test agent from Operations
    In Workspace Operations → click New Agent → select Sage (or researcher). Give it a quick test prompt:
    Operations — test prompt
    List the 3 most important recent developments in AI agent tooling. One sentence each. Use your web search tool.
    Watch it appear in the Overview grid with a live status indicator. This confirms Operations → agent spawning is working before you go bigger.

Phase 2 — Route a Mission Through Swarm

  1. Open Swarm in Hermes Workspace
    Navigate to localhost:3000/swarm. You'll see the Control, Board, Inbox, and Runtime tabs. The Control tab has the mission input and routing mode selector.
  2. Configure the Swarm mission
    In the Control tab, use this mission (or write your own):
    Swarm — Mission Input
    Produce a competitive intelligence brief on the top 3 open-source AI agent frameworks (excluding Hermes). For each: summarize key features, target use case, and one strength vs one weakness. Then synthesize a final 1-paragraph recommendation on where Hermes Agent is differentiated.
  3. Set routing mode and launch
    Select routing mode Auto (lets Swarm choose which workers to engage). Click Route Mission. Swarm creates a task graph: parallel worker tasks for each framework → a synthesis task that waits for all workers to complete.
  4. Watch the Board tab update
    Switch to the Board tab in Swarm. You'll see the worker tasks and their statuses. Switch to Runtime to see live worker activity logs.

Phase 3 — Monitor via Dashboard Kanban

  1. Open Dashboard Kanban as your command center
    Open localhost:9119/kanban in a separate browser tab (or window). This is your live project view. You should see the tasks Swarm created: worker tasks in Ready or In Progress, the synthesis task in Todo (waiting on all workers).
  2. Inspect a running worker's context
    Find a task that's In Progress. Open its drawer. Scroll down to the event timeline. You'll see spawned, heartbeat events as the worker runs. Click the task ID to get the full id, then from terminal:
    Terminal — watch live events
    hermes kanban tail <task_id>

    kanban tail streams all events for that task in real-time: spawned → heartbeat → completed (or blocked).

  3. Watch the synthesis task unlock
    When the first worker tasks move to Done, watch the synthesis task auto-promote from Todo → Ready in the Kanban board. This is the parent-link dependency gate in action — no human triggered it. The dispatcher picks it up on the next tick (click Nudge to force it now).
  4. Inspect the handoff — what did the synthesis worker receive?
    After the synthesis task moves to Ready, run:
    Terminal — see the handoff context
    hermes kanban context <synthesis_task_id>

    You'll see the ## Parent task results section populated with each completed worker's summary and metadata. This is the exact context the synthesis agent will start with — no explicit prompt engineering needed.

Real-World Use Case Examples

Overnight Code Review Sprint

Configure 4+ reviewer workers in Operations. Route all open PRs as Swarm tasks. Workers run overnight — each reviews one PR, leaves a kanban_complete(summary, metadata) with findings. A Scribe worker synthesizes a morning report. You wake up to a Done board and a summary in your inbox.

Multi-Repo Documentation Refresh

Swarm routes one task per repo to a builder worker (update docs) and one to a reviewer (check accuracy). Each reviewer task is a child of its builder sibling. A writer synthesizes the overall changelog when all repos are done. Kanban shows the progress across all repos in one view.

Automated QA Pass

Triage worker decomposes a test suite into individual test-file tasks. Builder workers run each in parallel. Reviewer worker gates on all builders completing — checks for flakes and regressions. Ops worker updates CI configuration. Full pipeline visible on the Kanban board throughout.

Competitive Intelligence Loop

Same as this exercise but on a cron. Weekly: Swarm kicks off 3 parallel researcher tasks (one per competitor), a writer synthesizes findings, a reviewer approves before the brief goes to your Slack via the messaging gateway.

hermes kanban swarm "Competitive intelligence brief: top 3 open-source AI agent frameworks" \ --worker researcher:"Research AutoGPT — features, use cases, strengths, weaknesses" \ --worker researcher:"Research CrewAI — features, use cases, strengths, weaknesses" \ --worker researcher:"Research LangGraph — features, use cases, strengths, weaknesses" \ --verifier reviewer \ --synthesizer writer
Expected Result: The swarm or pipeline command creates a task graph where parallel workers complete research and a later synthesis step waits for the earlier work to finish.

Creates an atomic graph: 3 parallel researcher tasks → 1 reviewer (waits for all 3) → 1 writer/synthesizer (waits for reviewer sign-off). Then watch it run: hermes kanban watch

Terminal — Manual P2 pipeline (full control)
Do this
Use this prompt in the appropriate chat, terminal, or field.
Paste into chat
# Parallel research workers (fan-out) T1=$(hermes kanban create "Research AutoGPT capabilities" --assignee researcher --json | jq -r .task_id) T2=$(hermes kanban create "Research CrewAI capabilities" --assignee researcher --json | jq -r .task_id) T3=$(hermes kanban create "Research LangGraph capabilities" --assignee researcher --json | jq -r .task_id) # Review gate — waits for all 3 research tasks T_REV=$(hermes kanban create "Review research findings for accuracy" \ --assignee reviewer --parent $T1 --parent $T2 --parent $T3 --json | jq -r .task_id) # Final synthesis — waits for review sign-off hermes kanban create "Write competitive intelligence brief" \ --assignee writer --parent $T_REV # Watch the pipeline run hermes kanban watch
Expected Result: The final pipeline output is a visible graph or audit trail showing completed worker tasks, downstream dependency gates, and the final summary or synthesis result.
⚡Operations and Swarm are both front doors to the same Kanban machinery. Operations is for manually launching named agents with explicit tasks. Swarm is for routing a mission to a pre-defined topology. Both create tasks on the same board — you can use both in the same workflow.
⚡The synthesis agent doesn't need special instructions. Because it receives each parent's summary + metadata automatically via the parent link, it already has the research findings in context when it starts. A clear task title and body is usually enough.
⚡Block a task to add human input mid-pipeline. If the reviewer worker blocks a task, it stays in Blocked until you add a comment with the clarification it needs, then click Unblock. The worker will pick it up on the next tick and read your comment as part of its context.
⚡Use hermes kanban runs <task_id> for post-mortems. After the pipeline completes, each task has a full attempt history: which profile ran it, how long it took, what the outcome was, and the structured handoff metadata. This is your audit trail.
