ELI10

A real, verified run — not a hypothetical. 4 agents ran in sequence through Operations: Researcher compares options, Writer drafts a recommendation + code, Vetter actually runs the code and catches a real bug, Orchestrator reports the final status in plain English. Every step below actually happened, including the mistakes.

🖥️ What ran, in order
  • Researcher (Sage) — plotly vs bokeh vs altair, 13 cited sources
  • Writer (Scribe) — recommendation + Python code stub
  • Vetter (Ops) — ran the code, caught a real bug → NEEDS REVISION
  • Orchestrator — 3-sentence status + next action
Operations — each agent is its own session; you relay one agent's output into the next agent's prompt. That relay is the handoff.

Why sequential, not parallel

Real orchestration = distinct agents + a real handoff, not concurrency. Sequential (researcher → writer → reviewer) is a legitimate pattern. What disqualifies a run: one agent doing every step itself, no matter how many tool calls it makes.

New Agent → pick a preset (Sage/Scribe/Ops) → this becomes one link in the chain.

⚡Clarify only upfront, never mid-flight: a mid-task question has nowhere to go if no one's watching. Conductor (Section 07) confirms the pattern: ask before dispatch; after that, assume + flag + keep going.

Confirmed bug + fix — zsh crashes Swarm workers

Tried hermes kanban swarm first — graph created fine, but every worker crashed instantly: the tmux launcher (swarm-dispatch.ts) captured exit codes with status=$?, and status is read-only in zsh. Verified directly (zsh -c 'status=$?' reproduces on demand); confirmed not a network issue (npm registry reachable). Fixed: renamed to exit_code.

ℹ️ Didn't affect the pipeline above

Only the Swarm/tmux path hits this bug. The Operations pipeline above works with zero fix needed.

Live Setup — Step by Step

  1. Confirm gateway + Workspace UI running (Phase 0)
  2. Operations → New Agent → pick a preset → rewrite description + system prompt to be generic (once)
  3. Send Researcher the task; wait for it to finish
  4. Copy its output into a new agent's (Writer) task message
  5. Copy Writer's output into a new agent's (Vetter) task message, ask for a verdict
  6. Send the Orchestrator a short status summary of all 3 results
  7. Review each agent's Chat session to audit the chain
⚡Expect "operation interrupted": happened twice in this run. "Please continue" fixed it every time — normal recovery, not a failure.
⚡NEEDS REVISION = success, not failure: the Vetter executing code and catching a real bug is the gate working correctly.
⚡Legit orchestration bar: 2+ distinct agents + a real handoff. Concurrency not required.
