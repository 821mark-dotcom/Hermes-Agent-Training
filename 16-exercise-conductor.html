Mission to Board

⏱ 20 minIntermediate
🎯 Exercise Goal

Give Conductor a single plain-English mission. Watch it decompose the goal into discrete subtasks that automatically appear on the Dashboard Kanban board. Understand the connection between a high-level intent and actionable task cards — without writing a single task yourself.

ELI10

In Exercise 1, you built the task board by hand. Now the agent builds it for you. You type one sentence describing what you want done. Conductor figures out the steps, assigns each one to the right specialist profile, and the Kanban board fills up automatically. Your job is to watch, understand, and verify — then approve or adjust what got created.

📋 Pre-requisite: Complete the Section 14 profile bootstrap first. Conductor needs at least researcher, writer, and reviewer profiles with descriptions to route tasks intelligently. Verify with: hermes profile list
🖥️ Hermes Workspace — What You'll Use
  • Conductor (localhost:3000/conductor) — type your mission, launch, watch agent decomposition (Nova/Pixel/Blaze)
  • Tasks (localhost:3000/tasks) — lightweight board view to see tasks appear in real-time
  • Dashboard Kanban (localhost:9119/kanban) — full board to inspect parent-child relationships and assignees
📋 Expected Output: 1 mission decomposed into 4–8 child tasks visible on the Kanban board. Each task assigned to a specialist profile. Parent-child dependency links visible in the card drawer. At least 2 tasks in Ready or In Progress.

Step-by-Step

  1. Before you start — check the board is empty (or clear it)
    Open Dashboard Kanban (localhost:9119/kanban). If you have tasks from Exercise 1, archive them: use multi-select (shift-click cards) → bulk action bar → Archive. Start clean so you can clearly see what Conductor creates.
  2. Open Hermes Workspace Conductor
    Navigate to localhost:3000/conductor. You'll see a mission text input and the agent roster (Nova / Pixel / Blaze). These are the agents Conductor will use to plan and decompose your mission.
  3. Type your mission
    Use this mission for the exercise (copy button below), or write your own one-sentence goal:
    Conductor — Mission Input
    Research the top 3 competitors in the AI-assisted code review space, then produce a 1-page competitive analysis brief with a recommendation on positioning.
  4. Launch and watch the decomposition
    Click Launch (or the equivalent send button). Watch Conductor think through the goal — you'll see it create a task graph: typically research tasks, an analysis task, a writing task, and a review task. Each gets assigned to the best-fit profile based on the descriptions you set in Section 14.
  5. Switch to Workspace Tasks to watch cards appear
    Open localhost:3000/tasks in another tab while Conductor runs. Cards will appear in the board as Conductor creates them. You'll see tasks show up in Triage → auto-promote to Ready as their parent tasks complete.
  6. Inspect the task graph in Dashboard Kanban
    Open localhost:9119/kanban. Click any task card to open the drawer. In the Dependency editor section, you'll see its parent tasks listed. The synthesis/writing task will show 2+ parents — it can't start until both research tasks are done.
  7. Watch a worker pick up a Ready task
    Click Nudge dispatcher. A task with an assignee in Ready status should move to In Progress within a few seconds. The worker has been spawned. Click ▸ Orchestration settings → confirm the profile that's running.
  8. Inspect what a worker sees before it runs
    From the terminal, find a task id for a task that's in Todo (waiting on a parent) and run:
    Terminal
    hermes kanban context <task_id>

    This shows exactly what the worker will see when it's spawned: title, body, current parent results (empty until parent completes), and the KANBAN_GUIDANCE lifecycle block.

Real-World Use Case Examples

Feature Kickoff

Mission: "Build a REST endpoint for weekly sprint reporting." Conductor decomposes into: API design → implementation → unit tests → docs → code review.

Market Research Sprint

Mission: "Analyze the 5 largest competitors for our product and identify gaps." Conductor creates parallel research tasks per competitor, then a synthesis + recommendation task.

Content Pipeline

Mission: "Produce a 3-part blog series on AI agents." Conductor fans out to 3 researcher tasks, 3 writer tasks (each with a research parent), and a final editor review.

⚡The decomposer's output quality depends on profile descriptions. If tasks are routing to the wrong profiles, run hermes profile describe <name> --auto to let Hermes generate better descriptions from each profile's installed skills.
⚡Conductor is a front door, not a special engine. It calls the same Kanban decomposition machinery as hermes kanban decompose. If you want to decompose without the Workspace UI, drop a task in Triage and click ⚗ Decompose in the card drawer.
⚡Don't over-specify the mission. Conductor is better at decomposing broad goals than precise step-by-step instructions. The more you pre-specify the steps, the less room the decomposer has to apply judgment. Save explicit step lists for when the decomposer consistently makes wrong routing choices.
⚡Check the parent task after fan-out. The original mission task becomes the parent of all children. When all children complete, that parent task wakes up so its assignee can judge whether the work is truly done — or add follow-up tasks.
