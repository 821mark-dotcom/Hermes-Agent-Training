Hermes Agent Web UI — The Built-in Dashboard

⏱ 10 minBeginnerIntermediate
ELI10

Hermes Agent has its own browser UI at localhost:9119 — no Workspace needed. It's lighter and faster for quick tasks: checking sessions, switching models, editing config, browsing skills, and chatting directly. Think of it as the "admin panel" for your agent.

⚡ Hermes Agent — Start the Dashboard Web UI
Terminal
Do this
Use this prompt in the appropriate chat, terminal, or field.
Paste into chat
hermes dashboard # opens http://localhost:9119 in your browser
Expected Result: The Dashboard reports the session list for the last week and identifies which session had the most tool calls.

Open http://localhost:9119 directly if the browser doesn't auto-open.

You
Do this
Ask for a higher-level usage review across multiple sessions and models.
Paste into chat
Review my last 20 Hermes sessions and tell me: which model I used most, which provider dominated my spend, and whether I should keep my default model or move expensive work to a cheaper profile for routine tasks.
Expected Result: Hermes summarizes recent usage and gives a practical recommendation on model choice, provider cost, or worker profile optimization.
⚡hermes serve = headless backend (no browser UI) — used by the desktop app. hermes dashboard = same backend but opens the browser UI. Use dashboard for daily use.
⚡Settings → Connection in the Workspace can update the backend URL live — no restart needed. Values persist to ~/.hermes/workspace-overrides.json.
⚡The dashboard Chat tab uses the same sessions as the CLI. They're fully interchangeable — start a chat in the terminal, continue it in the browser, and vice versa.
