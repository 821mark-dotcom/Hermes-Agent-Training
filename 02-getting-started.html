Getting Started — Install & First Launch

⏱ 10 minBeginner
ELI10

Three install paths. Pick the one that matches you. Run hermes setup, choose a model provider, and verify one clean chat works. That's it — don't add features until this baseline passes.

Install paths

🖥️ Desktop App (easiest)

macOS / Windows installer from the Hermes website. Includes CLI + desktop UI.

⚡ One-line CLI

Linux / macOS / WSL2 / Android. Installs to ~/.hermes/.

🐳 Docker

Self-hosters and home labs. Gateway + Workspace in one compose.

⚡ Hermes Agent — Add Your GitHub Copilot API Token

The fastest safe method is to generate a token locally with GitHub CLI and paste it into the Hermes setup prompt. Do this in a new terminal before running hermes setup:

  1. Install GitHub CLI (if needed):
    Terminal
    brew install gh
  2. Log in to GitHub:
    Terminal
    gh auth login
  3. Print your token — copy the output:
    Terminal
    gh auth token

When hermes setup asks for your Copilot API key, paste the token from step 3. You do not need to store it separately — Hermes persists it in ~/.hermes/.env after first use.

  1. Run setup wizard — choose your LLM provider and model
    hermes setup --portal  (one OAuth covers model + Tool Gateway tools)
  2. Verify chat works — one clean conversation before adding anything
    hermes or hermes --tui for the modern terminal UI
  3. Test session resume — ensures persistence is working
    hermes --continue  (should resume your last session)
  4. Run a health check — catches config issues early
    hermes doctor
  5. Start the gateway — only after base chat is confirmed
    hermes gateway run

Configuring Your Primary LLM

⚡ Hermes Agent only — Model configuration lives exclusively in the Hermes Agent Dashboard (localhost:9119). Hermes Workspace has no model settings of its own; it inherits whatever Hermes Agent is using.
⚡ Hermes Agent — Models page (localhost:9119/models)

🌟 Main Model

The model used for all chat sessions. Click CHANGE to pick a different provider or model. Takes effect on new sessions.

⚙️ Auxiliary Tasks

11 background tasks (vision, compression, kanban decomposer, etc.). Default is "all auto" — uses your main model. Click CONFIGURE only if you need task-specific overrides.

Recommendation: leave Auxiliary Tasks at AUTO. The auto setting inherits your main model for all background tasks. Changing individual tasks only makes sense for cost optimization at scale (e.g., pointing the decomposer at a cheaper model while keeping your main model on a frontier tier).

Hermes Agent Dashboard · Models · MAIN MODEL (CHANGE) · AUXILIARY TASKS "all auto" (CONFIGURE) · Mixture of Agents

Prefer editing config directly? The main model is stored in ~/.hermes/config.yaml:

Expected Result: The config snippet matches the active value for model/provider and is ready for use by Hermes Agent.
⚡Minimum 64K context: Hermes requires models with at least 64,000 context tokens. Most hosted models (Claude, GPT, Gemini) meet this easily. Local models need --ctx-size 65536.
⚡hermes setup --portal is the fastest path: one OAuth login covers a model + web search + image generation + TTS via Nous Portal.
⚡Don't add features until base chat works. Get one clean conversation first, then layer on gateway, cron, skills, or the workspace.
